# workbuddy-console

**WorkBuddy 宿主层的个性化配置管理器 + 生效验证器。**

> 改之前告诉你代价，改完证明它真的生效，升级后告诉你还在不在。

WorkBuddy（腾讯出品的桌面 AI 助手）里，"能改它行为的地方"散落在七八处：设置界面、隐藏配置文件、插件缓存目录、环境变量。这个项目把这些面收拢到一处，并为每一处改动提供**备份、还原、和生效验证**。

## 它解决什么问题

| 问题 | 现状 | 本项目的做法 |
|---|---|---|
| 改哪里、怎么改 | 靠手工试错 | 把手清单 + 差异预览 |
| 改了会不会坏 | 靠自觉 | 写入前自动备份（manifest + sha256），随时还原 |
| **改了到底生效没有** | **只能靠感觉** | **验证层：用数字告诉你进没进模型** |
| 升级后还在不在 | 升级后才发现失效 | 锚点校验 + 漂移告警 |
| 哪些改了也没用 | 反复白试 | 边界说明：哪些是厂商划死的 |

## 明确的范围边界

**只经营宿主层（客户端本体）；上游（腾讯网关 / 模型服务）碰不到，只如实呈现边界。**

具体地，本工具 **不做**：

- 不改网关流量、不做上游内容过滤的绕过
- 不改 `app.asar`、不改 Electron fuses
- 不改模型自身行为（模型的对齐倾向不在可达范围内）

## 关于 `historicalsource/`

该目录是**历史侦察资料（已冻结）**，含对 WorkBuddy 客户端的行为侦察结论、证据与脚本。

**它被排除在版本控制之外**，不会出现在本仓库中——其中包含第三方软件的代码副本与抓包记录，不适合公开分发。

本项目的设计**部分引用**了那些结论（结论级出处标注在 `AGENTS.md` 的引用索引、[`docs/recon-amendments.md`](docs/recon-amendments.md) 与各文档表格中），但**仓库只承载工程产物**。
