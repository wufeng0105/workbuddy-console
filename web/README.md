# web/ —— 前端控制台

> 任务导向的浅色工作台（2026-11-01 需求侧重构），**原生 ESM，不引构建链**（本地特权工具：依赖树越小越容易审计）。
> 启动：`node src/cli.mjs serve`（仅监听 127.0.0.1，令牌随启动生成）。
> 控制台 URL 会落在 `<用户数据目录>/state/console-url.txt` —— **令牌每次启动都变**，从那里复制。

## 结构

顶部横向导航（56px）+ 居中内容区（max-width 1200px）。总览 = 任务首页；**每个域只服务一个用户任务**，折叠长条是全站统一的列表组件（个性化 / 档位共用）。

## 六个域

| 域 | 内容 |
|---|---|
| **总览** | 任务首页：四张任务卡 + 健康状态条 + 最近动态台账 |
| **个性化** | 18 个把手分 4 组的折叠长条；双按钮「应用 / 还原」（最初基线写回，见 docs/framework.md「最初基线」） |
| **档位** | 长条折叠卡：切换（事务：预览 → 确认）/ 验证 / 删除 |
| **审批** | 双面**用颜色区分可信度**：绿「可可靠验证」/ 黄「无法保证」+ 三档策略卡 |
| **守护** | 三步向导（建包 → 漂移 → 重放）+ 备份时间线 + 操作台账 |
| **边界** | 六条"做不到"的事，每条附证据出处 |

## 文件

| 文件 | 内容 |
|---|---|
| `index.html` | 挂载点（只剩 `<div id="app">`） |
| `core.js` | 令牌 / API 封装 / DOM 工具 / 格式化 / 分组与边界常量 |
| `app.js` | 单页状态机：按域渲染（总览全宽；折叠卡组件全站复用） |
| `style.css` | 设计令牌（逐值取自 Stitch 设计稿，颜色**只用于标示状态**） |

## 编辑器按把手类型分流

| 把手类型 | 编辑器 |
|---|---|
| 身份文件（文本） | 大文本编辑器，带字符计数与**超限截断提示** |
| `toneStyle`（枚举锁死） | 下拉选择 |
| `rules.*`（规则矩阵） | **结构化操作**：选「从什么改成什么」+ 勾选作用动作，不手改 JSON |
| 风格内容 7 件（厂商参考件） | **不提供编辑**：只留「校验 / 拉取 / 还原」，拉取由校验结果驱动 |

## 双按钮（2026-11-01 用户定版）

- **应用** = 备份 → 写入。生效与否**用户自建会话自测**——验证能力保留在引擎与 API，页面不驱动验证
- **还原** = 当前版本账本（最初基线）的快照写回，改坏/反悔的保险

## 差异化警告（不是套话）

界面按把手的真实属性给出不同警告：

- 厂商文件 → 「升级可能覆盖它；写入需显式确认」
- `IDENTITY.md` → 「专家模式下不注入 —— 切档位时"名字"会静默消失」
- 内容超限 → 「超出部分静默丢弃」
- 非生效档位 → 「改它不会影响任何请求」
- 需停机把手 → 「要求 App 已退出才能写入」

## 硬约束（已落实）

- 前端**永不直接触碰文件系统**——一切经本地服务端 `/api/*`
- 鉴权：仅回环 + 随机端口 + 一次性 token（`X-WBC-Token`）；**绝不监听 `0.0.0.0`**
- 厂商文件写入必须**显式勾选确认**（铁律 5），服务端二次校验；厂商文件的基线还原同样要求显式确认
- 三态**不得合并**：`undetermined`（无法判定）渲染为黄色，**绝不显示成成功**（铁律 6）
- 无基线/无包时，状态标「未知」并给出建立路径而**不猜**（铁律 3）
