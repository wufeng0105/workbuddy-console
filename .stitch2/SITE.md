# SITE.md — workbuddy-console 前端重构（需求侧）

## 1. 为什么重做

现有三栏仪表盘（76/296/flex）把 18 个把手按**实现结构**排成长列表，用户找一个功能要翻列表、读术语、再猜操作顺序——**布局映射的是代码分类，不是用户任务**。本项目从需求侧重新推导信息架构。

## 2. 用户任务（jobs）→ 页面映射

| 任务 | 频率 | 页面 |
|---|---|---|
| J1 改一项个性化（人设/称呼/名字/风格/指令）并确认它生效 | 最高频 | `customize` 个性化向导 |
| J2 一键切换整套人设（N 套档位事务） | 高 | `profiles` 档位卡墙 |
| J3 让 WorkBuddy 少弹窗，并看清哪半可信 | 中 | `approval` 审批向导 |
| J4 升级后找回定制（漂移检测 → 重放） | 低危高价值 | `guard` 守护三步 |
| J5 知道哪里碰不得 + 动过什么 | 常驻 | `boundary` 边界卡墙 + `home` 总入口 |
| J0 快速到达以上任何任务 + 看健康状态 | — | `home` 任务首页 |

## 3. 布局重构（与旧版的决定性区别）

- **放弃 76px 窄 rail + 296px 长列表**，改为**顶部横向导航**（左 logo，中五域 tab，右运行状态徽章）——少一层嵌套，中文标签放得开
- 内容区**居中 max-width 1200px**，任务以**大卡片**呈现（标题 + 一句话 + 直达按钮），进卡片后是**向导式三步条**（编辑 → 预览差异 → 应用并验证），步骤条常驻页顶告诉用户「走到哪了」
- 每页只服务**一个任务**；18 个把手不再是平铺列表，而是按任务组织的卡与向导
