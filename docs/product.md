# 产品定位与范围

> 配套：`framework.md`（怎么造）｜`verification.md`（怎么证明）｜`handles.md`（把手清单）
> 上级：`../AGENTS.md`（工程契约）

## 一句话定位

> 一个 WorkBuddy **宿主层**的个性化配置管理器 + 生效验证器：
> **改之前告诉你代价，改完证明它真的生效，升级后告诉你还在不在。**

**A（管理器）为体，B（验证器）为魂。** 上游碰不到，只如实呈现边界。

## 层边界

| 层 | 包含 | 姿态 |
|---|---|---|
| **宿主层**（WorkBuddy 客户端本体） | 配置存储、提示词组装、插件、沙箱规则、审批、启动参数 | **经营**：改、备份、还原、验证 |
| **上游层**（本地 sidecar 之上的腾讯网关 + 模型服务） | 内容过滤闸、模型自身对齐、服务端下发的 managed 策略 | **只呈现**：如实写进边界说明，**不改** |

### 四种"拒绝/询问"必须分清

| 现象 | 层 | 能改吗 |
|---|---|---|
| 模型自己不愿答、说教、拒绝 | 上游 | ❌ |
| 模型答了、流被拦腰切断、usage 清零 | 上游（网关） | ❌ |
| 宿主弹审批 / 拦下工具调用 | **宿主层**（规则引擎 + 审批运行时） | ✅ |
| 模型在**回答文本**里问"要我先扫描还是直接改？" | **宿主层**（提示词层 `personal_files_safety`） | ✅（待实测，见 `verification.md` 第 4 条） |

> 后两者是**独立的两层**：弹窗审批由规则引擎执行；模型在文本里问由提示词条款驱使。规则改完还偶尔被"问"，多半是第二种。

## 专家档位模型

**一个"专家" = `SOUL.md`（身份立场）+ `style-*.md`（表达方式）+ `toneStyle`（档位指针）**

- **保持分工制**：style 管**表达方式**（语气、句式、结构、长度），SOUL 管**身份立场**（你是谁、和我的关系、底线、领域偏好），各不越界。
  - 二者是 user-context 模板里的**两个不同变量**（`{{ ToneStyleContent }}` / `{{ SoulContent }}`），同时渲染进同一段，**没有技术上的覆盖关系**。
  - **只有两边都写表达方式时才会"打架"**——那是语义矛盾，不是文件冲突。
- **两个必须建模的硬约束**（证据见 `recon-amendments.md`）：
  - **注入上限 10 000 字符 / 文件**：超出部分**静默丢弃**（`authority-snapshot.js:53 Ls=1e4`）。**"文件楔了" ≠ "模型看到了"**——这会直接污染 token 增量法的判据，因此 `verify` 的理论增量按**截断后**文本计算。
  - **专家模式跳过 `IDENTITY.md`**：切到专家档位时"名字"**静默消失**；`SOUL.md` 与 `USER.md` 两种模式都注入。
- **支持 N 套档位、一键切换**：官方 UI 只能有一个人设 + 七个固定档位；工具可以存 N 套并切换。
  - **7 是风格槽位数，不是专家数上限**；真正的限制是"**同时只有一个专家生效**"。
- **切换必须同时改 SOUL.md**：`toneStyle` 只决定读哪个 `style-*.md`，SOUL.md 不会跟着切。
- **提权成本可摊薄**：
  - `toneStyle`（`app-config.json`）与 `SOUL.md` 都在**用户目录** → 日常切换**零提权、零停机**，仅需**新会话生效**。
  - 只有 **`style-*.md` 的内容**在 `Program Files` → 7 份"预装配"一次（提权 1 次）→ 升级后若被还原，走一次重放（再提权 1 次）。

## 四个档位（"越界行为"配置）

**白名单 / 黑名单 / 分级不需要发明——它已经存在**：

```
sandbox.orderedRules
  三域：file / command / network
  每条 = { 路径/模式, isDirectory, read, write, delete }
                                    ↑       ↑       ↑
                              各可 allow / ask / deny
```

**本机实测现状**：file **135** 条（read: allow 133 / ask 2；**write: allow 86 / ask 49**）；command **0** 条；network **0** 条（语义待实测）。

**那 49 条 `write=ask` 就是要放开的东西；路径粒度就是"黑名单"能力。**

| 档位 | 宿主规则面 | 提示词面（`personal_files_safety`） |
|---|---|---|
| **原厂** | 135 条原样 | 原样 |
| **放宽**（建议默认） | 49 条 `ask`→`allow`；凭据类目录（`~/.ssh/` 等）仍 `ask` | 保留 No-Go Zones；去掉 "Scan = Read-Only" / "模糊先问" 这类强制询问条款 |
| **全放开** | 全 `allow` | 整段移除 |
| **自定义** | 用户逐条改矩阵 | 用户自己编辑文本 |

> ⚠️ **诚实边界**：改提示词能**降低**"模型问"的概率，**不能保证**。若"模型问"来自模型自身对齐（上游），改提示词**无效**。
> **"能不能治"本身就是一个待验证假设** → 而**把"治不了"如实报出来**，正是这个产品最硬的价值。

## 范围

### 纳入

| 把手 | 位置 | 提权 | 升级 |
|---|---|---|---|
| 称呼 / 名字 / 人设（USER / IDENTITY / SOUL.md） | `~/.workbuddy/user-<uid>-personal/` | 否 | 存活 |
| 指令（`customPrompt`）、回复风格（`toneStyle`） | `~/.workbuddy/app/app-config.json` | 否 | 存活 |
| `style-*.md` 内容 | `C:\Program Files\WorkBuddy\resources\app.asar.unpacked\resources\templates\style\` | **是** | **疑失效（待实测 #6）** |
| C 组 `prompt.tpl` / fragments（含 `personal_files_safety`） | `~/.workbuddy/plugins/cache/workbuddy-builtin/<plugin>/<版本哈希>/` | 否 | **失效** |
| 宿主规则矩阵 + 审批配置 | `~/.workbuddy/settings.json` | 否 | 存活（**是否被启动覆盖待实测**） |

### 排除

| 排除项 | 原因 |
|---|---|
| **长期记忆** | 当前被产品开关禁用（`cloud_memory_disabled`），受开关 + 云端 gate 双重控制 |
| **my-experts 自建专家** | 本期不做 |
| **模型切换 / BYOK** | 只是界面切换，不作承诺 |
| **上游 L4 内容过滤** | 客户端碰不到；不在范围 |

## 分期（竖切优先）

> 原则：**先用最少的把手数，验证技术风险最高的假设**，再横向铺开。

| 期 | 内容 | 为什么排在这 |
|---|---|---|
| **P0 竖切** ✅ | **一个把手（SOUL.md）走完六步 + 验证器跑通**（token 增量法） | 验证器是唯一无参照系可抄、技术风险最高、且决定产品价值命脉的部分。不接上它，"管理器立住了"这件事**无法被证明** |
| **P0b 自动对照** ✅ | 从 trace 自动取基线/观测（按**会话**切分） | 把"手工填数字"变成"改完点一下" |
| **P0c 控制台** ✅ | 本地服务端（仅回环 + 一次性 token）+ 原生 ESM 控制台 | 让东西真正可用 |
| **P1a 横向** ✅ | 其余个性化四项 + 两个把手工厂 | 同一条 user-context 尾段通道，复用同一套验证 |
| **P1b 多专家档位** ✅ | N 套「SOUL + style + customPrompt」一键切换（**多把手事务**） | 官方 UI 给不了多个可切换人设——这是最硬的差异化 |
| **P1c** ✅ | `style-*.md` 内容把手（安装目录，7 档） | 需提权（当前账号实际可写，探针如实报告）；**升级疑失效** → 为版本重放打底 |
| **P2a** ✅ | C 组根模板三模式（`prompt.tpl`）+ **标记法验证** | 换到请求**头部**通道；版本哈希定位；为 P3 的提示词面打底 |
| **P2b** ✅ | 宿主规则矩阵（三域）+ **重启后回读验证** | "越界审批自动同意"的规则面 |
| **P2c** ✅ | 版本重放（`bundle` 建包 → `drift` 检测 → `replay` 灌回） | 演进契约的执行细节：**存锚点键不存路径**，升级换目录也能重新定位 |
| **P3** | 审批自动同意（**两个面已备齐**：提示词面 P2a + 规则面 P2b） | 成败取决于待实测第 4 条 |

## 非目标

- 不改网关流量、不改 `app.asar`、不改 fuses（侦察已证明**没有必须改 asar 的场景**）
- 不写绕过上游内容过滤的**具体配方**（只记录边界位置）
- **不做通用平台**——服务于 WorkBuddy 这一个目标才活得久；通用化会把全部专属知识稀释成"可选适配细节"
